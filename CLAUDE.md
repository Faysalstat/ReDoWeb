# ReDoWebs

AI-powered website modernization platform. A user submits a URL to a small static website (≤3 pages, no server-rendered backend); the system crawls it, extracts a structured blueprint (`design.md`), and generates three tiered AI redesigns (Basic/Premium/Pro) the user can preview and pay credits to download.

## Settled decisions — do not re-litigate without the user's explicit sign-off

These were deliberately chosen after an extended requirements interview, sometimes overriding an initially "obvious" default. Don't silently swap them:

- **Backend framework is FastAPI, not Django** — despite Django's built-in admin being tempting for this project's heavy admin-panel requirements, the user explicitly chose FastAPI. Admin panel is built with **SQLAdmin** instead.
- **Credits, not multi-model tiers**: tiers are *prompt-strategy variants* of the *same* LLM (via OpenRouter), not different models. Tier differentiation is a prompt-engineering/rubric problem, tuned empirically (Milestone 10 in the plan).
- **Tiers are dynamic, not a fixed Basic/Premium/Pro enum**: tiers live in a `tiers` table (key, label, is_active, sort_order, download_credit_cost) that admins can enable/disable/rename/reorder/price. Disabled tiers are skipped entirely during generation. **Current build/test phase runs only `pro`** — see `backend/app/services/tier_service.py`, which is the one place tier-enabled logic lives; don't hardcode tier lists elsewhere.
- **Unified credit wallet**, ledger-based (`credit_transactions` table is the source of truth, `credit_wallets.balance` is a denormalized cache) — not a simple counter. Race-condition-safe spend uses `SELECT ... FOR UPDATE` row locking. See implementation-plan.md for why.
- **3 free signup credits are intentionally never enough to download anything** (cheapest download tier costs 3, but 1 credit is always spent on the initial generation first) — downloads always require a paid top-up. This is deliberate, not a bug.
- **>3 page sites are rejected outright**, not silently truncated to the first 3 pages.
- **No domain-ownership verification** before crawling — legal/ownership risk is mitigated only by a mandatory ToS checkbox at submission plus logging every submission for abuse/DMCA response. This was a conscious risk trade-off, flagged and accepted by the user, not an oversight.
- **`design.md` is semi-structured**: required YAML frontmatter (site_name, colors, logo path, fonts) + freeform markdown body. Not a fully structured form UI, not fully freeform prose.
- **Local disk storage in v1**, behind a `StorageBackend` abstraction — S3 migration is explicitly deferred, don't build it prematurely.
- **Apple SSO is deferred**, but the `auth_identities` table (not columns on `users`) exists specifically so it can be added later without a schema rework.
- **No WebSockets** — job-status is polled via REST (~3s interval) by design, not an oversight.
- **Testing bar**: unit tests only for credit/wallet math, tier pricing, Stripe webhook handling, and auth/permission checks. Crawler accuracy and AI output quality are verified manually — don't over-invest in e2e tests for subjective AI output.
- **Site generation is an agentic tool-calling loop via OpenRouter, not a single-shot completion** — the user only has an OpenRouter key (no direct Anthropic key), and OpenRouter's wire format is OpenAI-compatible, not Anthropic's native Messages API, so Anthropic SDK features (Tool Runner, Managed Agents, the actual Claude Agent SDK) don't apply here. `site_generator.py` hand-rolls the tool-call loop (`_run_agent_loop`) against `anthropic/claude-sonnet-4.5` (configurable via `REDOWEBS_GENERATION_MODEL`), giving the model `write_file`/`read_file`/`list_files` tools sandboxed to `generated/{tier}/`. The `backend/prompts/*.txt` design-strategy files are used as-is as the system prompt (they're already written as agent instructions) plus a code-appended constraint (no React/build tooling, plain HTML + Tailwind/Bootstrap via CDN). `app/ai/postprocess.py` runs after the agent loop (alt-text fallback, OG tags, WCAG contrast check, `sitemap.xml`).
- **`max_tokens` for generation must stay generous** (currently 16000) — an 8192 cap caused the model to truncate mid-tool-call while writing a full HTML page, producing invalid/incomplete JSON tool arguments that it then retried identically forever. If iteration limits are hit again, check `finish_reason` in the debug trace before assuming it's a prompt problem.
- **Frontend is Angular 20 (standalone components) + Tailwind CSS v4**, scaffolded in `frontend/`. It currently implements only the one flow the backend actually supports (submit URL → progress steps → live preview) — not the full route set (auth/dashboard/checkout/design-editor) from the implementation plan, since those backends don't exist yet. Don't build out those routes until their backend counterparts exist; keep the frontend honest about what's real. `home.component.ts` uses a **submit-once-then-poll pattern**, not sequential per-step calls: `POST /api/v1/projects` kicks off the whole Celery chain and returns immediately, then the frontend polls `GET /api/v1/projects/{id}` every 3s (RxJS `timer`/`switchMap`/`takeWhile`) until a terminal status. The old per-stage endpoints (`crawl()`/`extractBlueprint()`/`generate()` in `redowebs-api.service.ts`) are marked `@deprecated` and kept only for backend debugging — don't build new frontend features against them.
- **Generated sites are served to the frontend via a `/preview` static-file mount** (`app.mount("/preview", StaticFiles(directory=storage_root/"projects"))` in `main.py`) plus CORS for `http://localhost:4200` — this is how the Angular app iframes generated output directly from disk, no download step needed for preview. If you edit `main.py` during a manual (non-`--reload`) dev session, remember to restart uvicorn — a forgotten restart after adding CORS caused a real "405 on OPTIONS preflight" bug that looked like a code problem but wasn't.
- **Postgres (SQLAlchemy 2.0 + Alembic) is wired for the crawl/blueprint/generate pipeline, but it's a dual-write, not a migration**: DB rows (`Project`, `CrawlSnapshot`, `CrawlPage`, `Asset`, `Blueprint`, `GenerationJob`, `GenerationOutput`) are created/updated for queryability/audit, while `metadata.json` and `design.md` on disk remain what `crawl_service`/`blueprint_extractor`/`site_generator` actually read from — those weren't refactored to read from DB in this pass.
- **Celery (Redis-backed) now orchestrates the real pipeline**: `app/workers/celery_app.py` registers three tasks (`tasks_crawl.run_crawl_task`, `tasks_blueprint.extract_blueprint_task`, `tasks_generate.generate_tier_task`), chained per-tier in `routers/projects.py`'s `POST /api/v1/projects` via `tier_service.get_enabled_tiers()`. Each task updates `Project.status` and commits its own DB rows; **no auto-retry is configured on purpose** — any exception (transient or definitive) immediately marks the project `failed`/`rejected` via a broad `except Exception`, rather than half-building a retry policy that could leave a project stuck in an intermediate status forever. On Windows, the worker must run with `--pool=solo` (no `fork()` available).
- **This machine runs an unrelated Docker Compose project also named `standalone`** (`G:\Web modernizer\iac\standalone`) occupying the default Postgres/Redis ports — that's why `standalone/docker-compose.yml` sets an explicit `name: redowebs` and remaps host ports to `15432`/`6380`. Separately, Windows has a reserved TCP port-exclusion range on this machine (5433–5532, check via `netsh interface ipv4 show excludedportrange protocol=tcp`) that silently fails binds — don't assume a "port already in use" error is the only reason a Docker port mapping can fail.

## Working style for this project

- No fixed deadline — correctness and getting the core crawl→blueprint→generate loop right matters more than speed. Milestone 2 in the implementation plan (the core loop, no auth/payments) is the highest-priority thing to get right first.
- This is currently a solo-developer project — keep documentation resumable across sessions (update `docs/PROGRESS.md` as milestones complete) rather than relying on in-session memory or todo lists.
