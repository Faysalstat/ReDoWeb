## Known issues / deviations from plan

- Both the crawler and blueprint extractor were built as a **synchronous, DB-free slice** ahead of the plan's original milestone ordering, at the user's explicit request to prove the pipeline first. `project_id` is currently just a UUID used as a storage folder name — no `projects`/`crawl_snapshots`/`assets`/`blueprints` rows exist yet. Wiring this into Postgres + Celery (per implementation-plan.md §"Celery Task Chain") is still pending.
- Asset extraction currently only parses `<img src>` and `<link>` (icon/font) tags; stylesheet-embedded `@font-face`/`background-image` URLs are not yet parsed (noted as best-effort in `crawler/assets.py`).
- Blueprint extraction has no blueprint *versioning* yet (always overwrites `blueprint/design.md` in place) — the plan's version-history model (`is_current` flag, monotonic `version`) needs the DB layer to be meaningful.
- No unit tests written yet for the crawler or blueprint extractor (the plan's confirmed testing bar only requires unit tests for credit/wallet/pricing/webhook/auth logic; crawler/AI correctness is manual/exploratory per that decision). The phone-number regex and logo/hero-image heuristics have only been validated manually against a handful of real sites so far.
- Requires `REDOWEBS_OPENROUTER_API_KEY` set in `backend/.env` (gitignored) to run the vision call and the generation loop — not committed anywhere, must be supplied per-developer-machine. The user has an OpenRouter key only (no direct Anthropic key), which is why generation goes through OpenRouter's OpenAI-compatible tool-calling rather than Anthropic's native Tool Runner.
- **Post-processing pass now implemented** (`app/ai/postprocess.py`, run automatically at the end of `generate_site()`): fills in any missing/empty `alt` text (filename-derived fallback), injects Open Graph tags (`og:type/title/description/image/url`) if absent, runs a best-effort WCAG AA contrast check against the blueprint's color palette (flagged only, never auto-changed — a fix could contradict the design), and writes `sitemap.xml`. Verified standalone against the doggyduty.pet output: correctly left existing alt text alone, injected OG tags, and **caught a real accessibility issue** (orange `#ff7f00` primary vs white `#ffffff` accent = 2.53:1 contrast, below the 4.5:1 AA threshold). Found and fixed one bug during this: `og:image` initially used the blueprint's project-root-relative logo path (`snapshot/image/...`) instead of the output folder's actual `images/...` path.
- **Superseded (2026-08-27) — see the structured-JSON-pipeline entry below**: ~~Blueprint content-gap review added (2026-08-25)~~ described `blueprint_extractor.py`'s `CONTENT_GAP_SYSTEM_PROMPT`, checking only 4 fixed sections. That file and prompt no longer exist; the same "concurrent brand + content review calls, no-fabrication rule" shape survives but is now schema-driven across every Mandatory section, not just 4.
- **Structured JSON blueprint pipeline (2026-08-27), full rewrite of blueprint extraction/review**: `blueprint_extractor.py` deleted, replaced by `blueprint_schema.py` (Pydantic contract shared by `scraped.json` and `blueprint.json`), `blueprint_extraction.py` (deterministic, no AI), `blueprint_review.py` (the two-concurrent-OpenRouter-calls AI half), `blueprint_legacy_compat.py` (renders `blueprint.json` back into a `design.md`-shaped text blob so the unchanged `site_generator.py` keeps working), and `blueprint_pipeline.py` (orchestrates all three, fixed paths, always overwritten — no versioning yet, same as before). Schema is `meta` + `navigation` + `pages[]`, each page holding 14 named sections split into **Mandatory** (hero/about/services_features/faq/cta_section/footer/meta-text — safe for review to draft if missing) and **Optional/no-fabrication** (testimonials/gallery_portfolio/team/pricing/stats_social_proof/credentials_awards/contact/blog_news — left empty if the source lacks them, enforced in code via what each OpenRouter call's request/response shape includes, not just prompted). `Blueprint` model gained `tagline`/`favicon_path`/`scraped_json_storage_path`/`blueprint_json_storage_path` columns (migration `d81a4e6f9c02`, **not yet applied** — no Postgres running this session, run `alembic upgrade head` before relying on it) and `design_md_storage_path` is now nullable. Meta-review-call failure now degrades gracefully to the heuristic site_name/fonts/tone (explicit user decision, supersedes the old fail-hard rule — every meta field has a working fallback now). Full design: `docs/blueprint-json-pipeline-plan.md`.
- **Scraper completeness fix (2026-08-27): the schema's 14 sections are a template, not an exhaustive contract.** Found via manual testing against a real Elementor/WordPress site (fix2live.com): real customer testimonials never appeared anywhere in `scraped.json`, root-caused to two compounding gaps — (1) text extraction only read `<p>`/`<li>` tags, but the testimonial quote was wrapped in a bare `<div>` (very common on page-builder sites), and (2) the heading-anchored block model has no way to classify a widget with no governing heading at all. Fixed with three additions to `blueprint_extraction.py`: broadened leaf-`<div>`/`<span>` text capture (5+ words, no child elements, to avoid double-counting nested containers); a small extensible `WIDGET_EXTRACTORS` registry for known page-builder component signatures independent of the heading model (only an Elementor testimonial-carousel entry exists so far — real evidence only, no speculative entries); and a new `additional_sections` field on `PageSections` that preserves any real heading-anchored content matching none of the 14 named types under its own site-derived title, instead of being silently dropped (the previous behavior) or force-merged into `about`. `blueprint_review.py` extended to review `additional_sections` the same as Mandatory sections (may reword/consolidate, can never invent a new entry — merge only accepts response entries matching an existing `key`). Verified against the real site: testimonials went from 0 → 6 real quotes, plus 6 more real content blocks now surface via `additional_sections`. 8 new unit tests added.
- **Generation scoped to the home page only (2026-08-27)**: `site_generator.generate_site()`'s system prompt now always constrains output to a single `index.html`/`style.css`/optional `script.js`, regardless of how many pages the blueprint describes — matches the plan decision that additional pages are a later paid feature, not built by this function yet. Also gained an optional `template_override` param (path-traversal-checked) for picking one specific `prompts/*.txt` file instead of the normal random choice — real callers (`routers/generation.py`, `workers/tasks_generate.py`) never pass it, kept at its default `None`; it exists only for the debug route to repeatably test one design-strategy template. A prior debug-only `design_agent.py` module (built to prototype this before it was folded into the real function) was deleted once redundant.
- **Code-review pass (2026-08-27) on the above three changes found and fixed 5 issues**: two path-traversal bugs (`template_override` and debug-route `project_id` both built filesystem paths from unvalidated input — fixed with the same sandboxing pattern `generation_tools.py` already used, plus UUID validation on `project_id`); an icon-mismatch bug in the review merge (consolidated/reordered `services_features` items were paired with icons by list position, now matched by title first); dead CTA links (`javascript:void(0)` hrefs were copied verbatim into `cta_href` — now filtered, while still correctly keeping legitimate `tel:`/`mailto:`/anchor CTAs); and this file being stale (the old "two review calls" bullet still described the deleted `blueprint_extractor.py`).
- **Resolved (2026-08-03): blueprint-extraction token usage was previously discarded.** `blueprint_extractor.py`'s vision call returned usage as `_usage` (unused) — only the generation step's tokens were ever recorded, and only on `generation_outputs`, with no link to which user or model incurred them. Now both AI call sites write to the new `token_usage_logs` table via `token_usage_service.record_usage()` (see implementation-plan.md's Database Schema + Blueprint Extraction sections).
- `generation_max_tokens` had to be raised from an initial 8192 to 16000 — 8192 caused the model to truncate mid-tool-call while writing a full HTML page, producing invalid/incomplete JSON tool arguments it then retried identically forever (hit `finish_reason: "length"`, looped to `generation_max_iterations` with no progress). If iteration-limit failures recur (e.g., on a multi-page site with larger output), check the `_debug_trace.json` written to the output folder — it records `finish_reason`, assistant text, and tool call/result per iteration.
- No unit tests written yet for the crawler, blueprint extractor, or generation loop (the plan's confirmed testing bar only requires unit tests for credit/wallet/pricing/webhook/auth logic; crawler/AI correctness is manual/exploratory per that decision).

**Tiers are dynamic, not a fixed Basic/Premium/Pro enum** (per user request 2026-08-03): `backend/app/services/tier_service.py` is the single source of truth for which tiers exist and which are enabled (`Tier(key, label, is_active, sort_order, download_credit_cost)`). Currently only `pro` is `is_active=True`; `basic`/`premium` are defined but disabled. This is an in-code stand-in for the future DB-backed `tiers` table (see implementation-plan.md) — admin on/off toggling isn't real yet (no admin panel exists), but all calling code should go through `tier_service.get_enabled_tiers()` so the eventual DB swap doesn't ripple through the codebase.

- The frontend now submits once (`POST /api/v1/projects`) and polls `GET /api/v1/projects/{id}` every 3s rather than calling three endpoints sequentially from the browser. A page refresh mid-flow still loses the poll subscription (no resume-from-URL/localStorage yet), but the backend chain keeps running server-side regardless, and re-fetching status by `project_id` would reconstruct UI state if that were wired up.
- Hit one real bug while wiring the frontend: added CORS middleware to `main.py` but forgot to restart the (non-`--reload`) uvicorn process — the browser's preflight `OPTIONS` request got a 405 until the restart. Worth remembering when editing `main.py` during manual (non-reload) dev sessions.
- API base URL (`http://localhost:8123`) is hardcoded in `frontend/src/app/core/api-config.ts` — no environment-based config yet (fine for solo local dev, will need proper Angular environment files before any real deployment).
- **Local dev environment quirks worth remembering**: this machine already runs an unrelated Docker Compose project also named `standalone` (`G:\Web modernizer\iac\standalone`) whose containers occupy the standard Postgres/Redis ports — `standalone/docker-compose.yml` sets an explicit `name: redowebs` and remaps host ports to **15432** (Postgres) and **6380** (Redis) to avoid colliding with it. Separately, Windows has a reserved TCP port-exclusion range (5433–5532 on this machine, checked via `netsh interface ipv4 show excludedportrange protocol=tcp`) that silently fails any bind attempt in that range — that's why Postgres isn't on the more obvious `5433`.
- `DATABASE_URL`/`database_url` setting defaults to `postgresql+psycopg://redowebs:redowebs@localhost:15432/redowebs`, matching the compose file's credentials and remapped port.
