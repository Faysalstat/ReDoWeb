## Known issues / deviations from plan

- Both the crawler and blueprint extractor were built as a **synchronous, DB-free slice** ahead of the plan's original milestone ordering, at the user's explicit request to prove the pipeline first. `project_id` is currently just a UUID used as a storage folder name — no `projects`/`crawl_snapshots`/`assets`/`blueprints` rows exist yet. Wiring this into Postgres + Celery (per implementation-plan.md §"Celery Task Chain") is still pending.
- Asset extraction currently only parses `<img src>` and `<link>` (icon/font) tags; stylesheet-embedded `@font-face`/`background-image` URLs are not yet parsed (noted as best-effort in `crawler/assets.py`).
- Blueprint extraction has no blueprint *versioning* yet (always overwrites `blueprint/design.md` in place) — the plan's version-history model (`is_current` flag, monotonic `version`) needs the DB layer to be meaningful.
- No unit tests written yet for the crawler or blueprint extractor (the plan's confirmed testing bar only requires unit tests for credit/wallet/pricing/webhook/auth logic; crawler/AI correctness is manual/exploratory per that decision). The phone-number regex and logo/hero-image heuristics have only been validated manually against a handful of real sites so far.
- Requires `REDOWEBS_OPENROUTER_API_KEY` set in `backend/.env` (gitignored) to run the vision call and the generation loop — not committed anywhere, must be supplied per-developer-machine. The user has an OpenRouter key only (no direct Anthropic key), which is why generation goes through OpenRouter's OpenAI-compatible tool-calling rather than Anthropic's native Tool Runner.
- **Post-processing pass now implemented** (`app/ai/postprocess.py`, run automatically at the end of `generate_site()`): fills in any missing/empty `alt` text (filename-derived fallback), injects Open Graph tags (`og:type/title/description/image/url`) if absent, runs a best-effort WCAG AA contrast check against the blueprint's color palette (flagged only, never auto-changed — a fix could contradict the design), and writes `sitemap.xml`. Verified standalone against the doggyduty.pet output: correctly left existing alt text alone, injected OG tags, and **caught a real accessibility issue** (orange `#ff7f00` primary vs white `#ffffff` accent = 2.53:1 contrast, below the 4.5:1 AA threshold). Found and fixed one bug during this: `og:image` initially used the blueprint's project-root-relative logo path (`snapshot/image/...`) instead of the output folder's actual `images/...` path.

That file and prompt no longer exist; the same "concurrent brand + content review calls, no-fabrication rule" shape survives but is now schema-driven across every Mandatory section, not just 4.
- **Structured JSON blueprint pipeline (2026-08-27), full rewrite of blueprint extraction/review**: `blueprint_extractor.py` deleted, replaced by `blueprint_schema.py` (Pydantic contract shared by `scraped.json` and `blueprint.json`), `blueprint_extraction.py` (deterministic, no AI), `blueprint_review.py` (the two-concurrent-OpenRouter-calls AI half), `blueprint_legacy_compat.py` (renders `blueprint.json` back into a `design.md`-shaped text blob so the unchanged `site_generator.py` keeps working), and `blueprint_pipeline.py` (orchestrates all three, fixed paths, always overwritten — no versioning yet, same as before). Schema is `meta` + `navigation` + `pages[]`, each page holding 14 named sections split into **Mandatory** (hero/about/services_features/faq/cta_section/footer/meta-text — safe for review to draft if missing) and **Optional/no-fabrication** (testimonials/gallery_portfolio/team/pricing/stats_social_proof/credentials_awards/contact/blog_news — left empty if the source lacks them, enforced in code via what each OpenRouter call's request/response shape includes, not just prompted). `Blueprint` model gained `tagline`/`favicon_path`/`scraped_json_storage_path`/`blueprint_json_storage_path` columns (migration `d81a4e6f9c02`, **not yet applied** — no Postgres running this session, run `alembic upgrade head` before relying on it) and `design_md_storage_path` is now nullable. Full design: `docs/blueprint-json-pipeline-plan.md`.
- **Scraper completeness fix (2026-08-27): the schema's 14 sections are a template, not an exhaustive contract.** Found via manual testing against a real Elementor/WordPress site (fix2live.com): real customer testimonials never appeared anywhere in `scraped.json`, root-caused to two compounding gaps — (1) text extraction only read `<p>`/`<li>` tags, but the testimonial quote was wrapped in a bare `<div>` (very common on page-builder sites), and (2) the heading-anchored block model has no way to classify a widget with no governing heading at all. Fixed with three additions to `blueprint_extraction.py`: broadened leaf-`<div>`/`<span>` text capture (5+ words, no child elements, to avoid double-counting nested containers); a small extensible `WIDGET_EXTRACTORS` registry for known page-builder component signatures independent of the heading model (only an Elementor testimonial-carousel entry exists so far — real evidence only, no speculative entries); and a new `additional_sections` field on `PageSections` that preserves any real heading-anchored content matching none of the 14 named types under its own site-derived title, instead of being silently dropped (the previous behavior) or force-merged into `about`. `blueprint_review.py` extended to review `additional_sections` the same as Mandatory sections (may reword/consolidate, can never invent a new entry — merge only accepts response entries matching an existing `key`). Verified against the real site: testimonials went from 0 → 6 real quotes, plus 6 more real content blocks now surface via `additional_sections`. 8 new unit tests added.
- **Generation scoped to the home page only (2026-08-27)**: `site_generator.generate_site()`'s system prompt now always constrains output to a single `index.html`/`style.css`/optional `script.js`, regardless of how many pages the blueprint describes — matches the plan decision that additional pages are a later paid feature, not built by this function yet. A prior debug-only `design_agent.py` module (built to prototype this before it was folded into the real function) was deleted once redundant. **Superseded (2026-08-31) — see the "AI-generated design system" entry below**: ~~gained an optional `template_override` param... for picking one specific `prompts/*.txt` file instead of the normal random choice~~ — that mechanism, and the 6 static template files themselves, no longer exist.
- **AI-generated design system replaces the 6 static style templates (2026-08-31)**: `backend/prompts/*.txt` (business_corporate/flatDesign/Industrial/material/modernDark/organic, picked by `random.choice` with zero tier-awareness) is gone. In its place, `app/ai/design_system_generation.py` adds one new AI step — `generate_design_system()` — run once per project (not once per tier) in `blueprint_pipeline.run_blueprint_pipeline()` right after `review_blueprint()`, writing `blueprint/design_system.json`. It reads the blueprint's real, already-extracted `tone`/`colors`/`fonts`/section-presence, deterministically pre-filters (`select_candidate_recipes()`, keyword-matched, no LLM) a small curated recipe library (`backend/prompts/recipes/*.md`, 10 recipes — 8 adapted from `agent/references/style-recipes/` plus 2 custom ones for verticals that library doesn't cover, `industrial-craft`/`vibrant-friendly`, folding in the genuinely useful content from the old Industrial/Material templates) down to 2-3 candidates, and asks the model to resolve a concrete spec anchored in one of them — never inventing a look with no stated anchor. The real extracted colors always override anything the model echoes back for them (code-enforced in `_normalize_spec`, same pattern as `blueprint_review.py`'s merge functions); the model is only trusted for a color-derivation *rule* text (e.g. "hover = +8% lightness"), applied at generation time via real CSS `oklch()`/relative-color-syntax rather than AI-guessed hex. Fonts are the opposite — the model's pick wins over the site's original (often generic, e.g. the literal fallback default is "Inter"/"Inter") fonts, since typography is the lowest-priority brand-recognition signal. Degrades the same way the meta-review call does: on `OpenRouterError`, falls back to `build_fallback_design_system()` (top keyword-matched recipe + real colors/fonts, no LLM), so a failed call never fails the pipeline; `site_generator.generate_site()` applies the same fallback if `design_system.json` is somehow missing at generation time. `site_generator.py` assembles its system prompt from a new static `CRAFT_PRINCIPLES` block (craft/anti-fabrication guidance distilled from `agent/SKILL.md`'s web-design-engineer skill — only the parts that don't fight whatever the resolved design system calls for) + the per-project spec rendered as plain text (`_render_system_prompt()`, no AI call) + the existing `TECH_CONSTRAINTS`. New debug route `POST /api/v1/debug/design-system/{project_id}` (optional `recipe_override` to force one candidate) added alongside the existing scrape/review/design-md/generate stages; `/generate`'s old `template` query param is gone. 16 new unit tests (`test_design_system_generation.py`, `test_site_generator.py`, `test_blueprint_pipeline.py`) cover the deterministic pre-filter, the fallback builder, the real-colors-always-win normalization, and the plain-text renderer.
